# AI 타로 해설 서버

## 실행과 배포

`pip install -r requirements.txt` 후 환경변수를 설정합니다. 개발 서버는 `python app.py`, 운영 서버는 저장소의 `Procfile` 명령으로 실행합니다.

- `DEEPSEEK_API_KEY`: AI 서비스 키. 누락되면 503 오류를 반환하며 가짜 해설을 만들지 않습니다.
- `ALLOWED_ORIGINS`: 실제 프론트엔드 주소를 스킴까지 포함하여 쉼표로 구분합니다. Safari/PWA에서 사용하는 주소, www 유무가 다른 주소도 각각 명시해야 합니다.
- `AI_MAX_CONCURRENT`: 프로세스당 AI 해설 생성 상한, 기본 4. Gunicorn은 8개 스레드로 해설 대기 중에도 다른 요청을 처리합니다.
- `PORT`: 호스팅 서비스가 지정한 포트.

프론트엔드 `NEXT_PUBLIC_API_URL`에는 외부에서 접근 가능한 백엔드 HTTPS 주소를 지정하고 다시 빌드해야 합니다. **아이폰에서 localhost는 아이폰 자신이므로 운영 빌드에 localhost 주소를 넣으면 안 됩니다.** 변수 생략 시 현재 사이트의 `/api`를 사용하므로 해당 경로를 백엔드로 전달하는 프록시가 필요합니다. 로컬의 `.env.local`은 개발용으로 유지합니다.

백엔드와 프론트엔드를 함께 배포해야 새 응답 처리·프롬프트가 적용됩니다. 소스 변경이나 로컬 빌드만으로 운영 서버가 바뀌지는 않습니다.

## 해설 처리

1. 카드, 방향, 질문, 스프레드를 검증합니다.
2. 질문 원문은 AI 입력의 JSON 데이터에 한 번만 보존합니다. 질문을 인용·복창·요약하는 확인 도입문은 표시하지 않고 카드 해석과 조언부터 시작합니다. 감정·부정 표현·시점·주어를 카드보다 우선하도록 지시하며, 모호한 감정이나 말하지 않은 현재/과거 문제는 단정하지 않습니다.
3. 선택한 카드의 위치·방향·해당 방향의 의미를 전달해 AI를 한 번 호출하고 조언 본문만 생성합니다. 별도 초안/검수 호출은 없습니다. 부정적 카드는 현재 감정을 뒤집는 진단이 아니라 미래의 조건부 행동 조언으로 풀이합니다.
4. 출력은 SSE로 전달하고 완전하게 끝난 경우에만 완료 이벤트를 보냅니다. AI를 기다리는 동안 10초마다 연결 유지 신호를 보냅니다.

질문 유무와 관계없이 서버 요청당 AI 생성 호출은 1회입니다. 출력 상한은 개별 카드 350토큰, 오늘 600토큰, 흐름 900토큰, 종합 1200토큰입니다. 실제 사용량은 입력과 생성된 출력에 따라 달라지며, 상한 전체가 항상 사용되는 것은 아닙니다.

서버 SDK의 숨은 자동 재시도는 껐습니다(`max_retries=0`). 일시적인 연결 오류는 프론트엔드에서 동일 질문/카드로 한 번만 자동 재시도하고, 계속 실패하면 수동 재시도를 제공합니다. 재시도는 새 생성 요청이므로 추가 토큰이 발생할 수 있습니다. 서버 대기 시간은 최대 90초이며 프론트엔드는 요청당 110초 후 취소합니다.

단일 생성 프롬프트는 모든 의미 오류를 보장해 막지는 못합니다. 특히 반어법이나 모호한 복합 문장은 감정을 추정하지 않도록 처리하며, 출력의 완벽한 의미 일치를 보장한다고 주장하지 않습니다.

연결 유지 신호는 프록시의 idle 연결 종료를 줄입니다. Gunicorn worker timeout은 HTTP idle timeout과 별개이며, gthread 설정으로 요청 대기 중에도 worker가 응답합니다. 프록시가 있다면 SSE 버퍼링을 끄고 read timeout을 서버의 최대 대기 시간보다 길게 설정해야 합니다. [Gunicorn 문서](https://docs.gunicorn.org/en/stable/settings.html#timeout)

## 검증

```sh
python3 -m unittest discover -s tests -v
```

테스트는 외부 AI/Discord 호출 없이 입력 검증, 원문 보존, 주기적 heartbeat, 타임아웃, 동시 요청 상한, 취소, 미완성 응답, 질문 유무와 모든 스프레드/언어에서 단일 생성 호출, 원문 중복 방지를 검증합니다. 프론트엔드에서는 `node --test tests/*.test.mjs`로 UTF-8/이벤트 분할, JSON 응답, 잘린 연결, 재시도, 취소와 해설의 문장·문단 분리를 검증합니다.

실제 기기 재현 시 Safari와 홈 화면 PWA에서 각각 오늘/흐름/종합 해설, Wi-Fi↔모바일 데이터 전환, 앱 전환 후 복귀를 확인합니다. 오류가 지속되면 실패 시각, HTTP 상태, 사용 주소, 서버/프록시 로그를 대조합니다. 사용자 질문 원문이나 API 키를 로그에 추가하지 않습니다.
